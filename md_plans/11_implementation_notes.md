# 11 — Заметки по реализации Rust-скелета

Статус: собирается (`cargo build`, 0 warnings), GUI на egui, движок 60 Гц, OSC :7700. Ниже — решения и отклонения от TD, зафиксированные при кодировании.

## Захват системного звука (R6) — подтверждённый способ
Система пользователя: **PulseAudio** (не PipeWire; `pactl` есть, `pw-cli` нет). Monitor-источники существуют:
- `alsa_output.pci-0000_08_00.6.analog-stereo.monitor` — системный выход (колонки),
- `alsa_output.pci-0000_01_00.1.hdmi-stereo.monitor` — HDMI.

**cpal обновлён 0.15 → 0.18.** В 0.15 был баг ALSA-таймстампов: при захвате с устройств, идущих через pulse-плагин, cpal-поток паниковал (`get_htstamp 0.0 was earlier than get_trigger_htstamp` и `assertion left==right: -1 vs 8`, RustAudio/cpal #630/#604). В 0.18 таймстамп-логика переписана и паники убраны → **это корень зависаний при выборе устройств**. API-правки под 0.18: `Device::name()` → `description()?.name()`; `SampleRate`/`ChannelCount` теперь алиасы `u32`/`u16` (без `.0`); `build_input_stream` берёт `StreamConfig` по значению.

`cpal` (ALSA-хост) всё равно **не** показывает Pulse-мониторы как устройства и отдаёт «сырые» имена `hw:CARD=…`. Поэтому системный звук берём мимо cpal:
- источники — из `pactl list sources` (`LC_ALL=C` для стабильных меток), с **человекочитаемым Description** (напр. «Monitor of Ryzen HD Audio Controller…»), детект монитора по `Monitor of Sink:`/суффиксу `.monitor` (`audio::list_pulse_sources`);
- при выборе монитора захват идёт **процессом `parec`** (`parec -d <src> --format=float32le --channels=1 --rate=48000`), raw f32le читается из stdout в потоке и пушится в кольцо (`AudioInput::open_pulse`; RAII-`PulseCapture` при drop делает `kill`+`wait`+`join`, зависнуть не может — kill закрывает pipe → read=EOF → поток выходит). Без новых крейтов (`parec` из `pulseaudio-utils`).
- железо (обычные ALSA-устройства) — через cpal (`open_cpal`).
- В GUI: комбобокс «pulse source (monitor)» показывает Description, приоритетнее ALSA-device; ALSA-комбо блокируется при выбранном pulse-источнике. Галочка «предпочитать мониторы» авто-выбирает первый monitor.

**Выбор каналов (многоканальные интерфейсы).** cpal-вход даунмиксил ВСЕ каналы в моно — неверно для устройств с 18 in/out (микшер). Добавлено `InputCfg.channels_pick: Vec<usize>` (0-based индексы). Пусто → среднее всех; иначе усредняются только выбранные (`audio::mono_pick`/`mono_pick_map`). В GUI под ALSA-комбо появляется ряд тумблеров каналов (число берётся из `default_input_config().channels()` устройства), метка устройства показывает `[Nch]`. Для parec-пути (pulse-монитор, обычно stereo) выбор пока не применяется. Замечание: если реальный интерфейс под-репортит каналы в default-конфиге, перейти на max из `supported_input_configs()`.

**Микрофон в списке.** Онбордовый вход отображается как `HD-Audio Generic, ALCS1200A Analog [2ch]` (сырое ALSA-имя). Записи `[0ch]` — ALSA-плагины/ресемплеры, не реальные входы (открывать их не нужно). Pulse-источники сейчас содержат только 2 монитора выходов — аналоговый вход в PulseAudio не заведён, поэтому микрофон берётся через первый (ALSA) дропдаун.

**PipeWire native:** у cpal нет нативного PipeWire-бэкенда, и на этой системе звук идёт через **PulseAudio-сервер** (не PipeWire; `pw-cli` отсутствует). Так что «нативный PipeWire» тут неприменим — дружелюбные имена и захват выхода уже дают `pactl`+`parec`. Если позже система переедет на PipeWire, `parec`/`pactl` продолжат работать через слой `pipewire-pulse` без изменений в коде.

## Точность поведения (приведение к TD)
- **Сглаживание полос** — теперь скользящее среднее (boxcar) окном `width` секунд, как TD Filter CHOP (`dsp::SmoothFilter`), вместо one-pole. Длина окна = `round(width_s / dt)` на 60 Гц. Это даёт корректную форму атаки/спада огибающих low/mid/high.
- **Lag** (`dsp::Lag`) — асимметричная модель: целевая скорость `(target−y)/lag` (lag_up/lag_dn), ограничение ускорения `accel·dt` (accel_up/accel_dn). Stateful, состояние не сбрасывается (R3).
- **rythm** — **onset по спектральному flux**. Flux (Σ положительных приращений магнитуд) нормируется пик-фолловером (`flux/flux_peak`, `flux_peak` затухает ×0.999) в стабильную шкалу **0..1**, дальше идёт в детектор как обычный триггер (порог ~0.45, retrigger 0.12 с). Раньше был `flux×1000` против порога ~48 из большого маппера → сигнал почти всегда превышал порог и лампа «свистела»; теперь rythm не завязан на 0..6-маппер (он остаётся для будущего) и ведёт себя как чёткий onset. `fms`/`sms` пока от полной энергии спектра (диапазоны из `03`).
- **Полосы/детекторы** считаются на нефильтрованном RMS полос до сглаживания — как в дампе (kick по low-RMS `analyze1`, snare по high-RMS ×4 `math16`). Пред-гейны low/mid/high = 1/2/4.
- **Все параметры дампа** заведены в `config.rs` с дефолтами из `07`: пороги, гейны, add, smooth, retrigger 0.08, компрессор −20.6/0.638/+6.9, мапперы (preoff/gain/postoff/torange), сигмоиды kick `{0.7,5.4,0.3}` / snare `{0.9,2.1,0.5}`, lag 2/4 + accel 1/3.

## Отклонения / калибровка (не 1:1, помечено)
- Фильтры — RBJ-биквады (каскад ≈ rolloff/6 секций), не идентичны TD `audiofilter`, но частоты/типы/резонанс совпадают.
- FFT-центроид считается напрямую по бинам (`Σ i·|X| / Σ|X|`), без TD-шаффла 440; диапазон ремапа 18..32 сохранён — калибровать под вход.
- Компрессор — упрощённый downward (по модулю сэмпла), не полный `audiodyna`.
- `fms/sms` семантика приблизительная (энергия спектра с разными окнами/ремапами).
- Абсолютные величины rythm-flux зависят от FFT-масштаба → финальная калибровка через GUI/пресеты.

## GUI
- Верхняя панель — **большие лампы** по **огибающим** (`*_env`: импульс → плавный спад ×0.86/тик, иначе вспышки в 1 кадр не видны): `KICK`/`SNARE`/`RYTHM` + `LOW/MID/HIGH`. Яркость ∝ значению.
- Левая панель: источник (pulse/ALSA), пре-компрессор, RMS-power (R2), DSP-гейн, OSC, пресеты (сохранить/загрузить ron). Ко всем крутилкам — hover-подсказки с описанием константы.
- Центр: полосы **side-by-side** (колонки), детекторы, адаптив. При включённом адаптиве **gain полос** и **пороги kick/snare** становятся неактивными (правятся автоматом) — видно, что «крутится, но не применяется». rythm-порог всегда ручной.
- Сигмоиды: компактный редактор с превью + кнопка «⧉ окно» — открывает **отдельное окно** с крупным резайзящимся графиком. На графике две точки: голубая — вход x (пришло с маппера), жёлтая — выход/порог (ушло).
- Правая панель: метры уровней/детекторов, спектр, control-выход, ошибки аудио.

## Структура (как в `09`)
`audio` (cpal+pulse) · `dsp` (biquad/rms/lag/smooth/spectrum) · `detect` (beats/counters) · `control` (адаптив) · `osc` (rosc) · `engine` (60 Гц worker) · `gui` (egui) · `config`+`shared`.
