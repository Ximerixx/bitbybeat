# 09 — Оптимизации и упрощения для Rust-порта

Предложения основаны исключительно на эталоне `.toe.dir`. Разделены на: (A) исправления найденных несоответствий, (B) архитектурные упрощения, (C) производительность, (D) удобство/файнтюн.

> ⚠️ **Приоритет правок заказчика (`10_customer_requirements.md`).** Мёртвые ноды **не удаляем** — делаем переключаемыми (заказчик включает их по ситуации). Пункты A2/A3/A5 ниже скорректированы: вместо «убрать/не портировать» — «портировать как опциональное с bypass».

## A. Исправить несоответствия дампа (важно для корректности)
1. **Единый вход.** Свести источники в один буфер → и в анализ, и в адаптивную RMS-ветвь. В дампе анализ читает внутренний mp3, а адаптив — live ASIO (Находка №1). В порте один `input`; источник = **устройство** (в т.ч. monitor выходного устройства), файл — опционально (см. `10.R6`).
2. **Компрессор — опциональный пре-компрессор.** Калиброванный компрессор (`−20.6 / 0.638 / +6.9 dB`) в дампе висит на мёртвой `audiodyna1` (Находка №2). Портируем как **включаемый** пре-компрессор на входе (дефолт bypass, значения как в дампе) — `10.R1`.
3. **`Highgain`.** По умолчанию из `highControlGain1` (gain 1.93). Ноду `highControlGain` (0.77) **тоже портируем** — как альтернативу с переключателем (`10.R1`).
4. **`Rythmthresh`** — выражение в дампе битое (`op('rythmControlThreshold')[0] op('rythmControlGain')[0]`, второй оп отсутствует). Брать `rythmControlThreshold[0]` (диапазон 0..6) и калибровать; не воспроизводить кэш 69.9.
5. **`merge2(audiodyna1, audiodyna1)`** — дубликат входа для VST; логически не нужен, но не является «фичей» — просто не воспроизводим этот артефакт (сам компрессор — по п.2).

## B. Архитектурные упрощения
6. **Схлопнуть цепочки TD-нод в функции.** Каждая полоса в дампе — 6–7 нод (analyze→math→math→limit→add→filter→switch). В Rust это одна функция:
   ```rust
   fn band_level(rms: f32, thresh: f32, gain: f32, add: f32, smooth: &mut Filter) -> f32 {
       let lvl = ((rms - thresh) * gain).clamp(0.0, 100.0);
       smooth.process(lvl + add)
   }
   ```
7. **Единый control-граф.** Адаптив (RMS→lag→мапперы→сигмоиды) — чистая функция `f(level) -> ControlState` на 60 Гц. Вынести коэффициенты в структуру конфига (все `preoff/gain/postoff/torange` из `07`).
8. **Сигмоиды как параметрический тип** `Sigmoid { ceil, k, center }`: kick=`{0.7, 5.4, 0.3}`, snare=`{0.9, 2.1, 0.5}`. Редактор в GUI (превью кривой).
9. **Генераторы (Low_Base/Mid_Base/High_Mid/Jumper/Zig_Zagger)** — вынести в опциональный модуль «generators», не в MVP. Это не измерения, а декоративные огибающие/события для визуалов. MVP: полосы + детекторы + доли + OSC.
10. **Счётчики долей** обобщить: один `BeatCounter{mod: 4|8|16}` на kick и на snare, вместо 6+ нод × 3 копий (`Count_Analysis` встречается 3 раза — в топе, в Jumper, в Zig; в порте одна реализация).
11. **GUI-ноды дампа игнорировать.** ~600 из 757 нод — слайдеры/кнопки/индикаторы/текст палитрного компонента. Логика GUI переписывается на egui с нуля; из дампа берём только диапазоны/дефолты параметров (`07`).

## C. Производительность (главная причина порта — TD «прожорлив»)
12. **Разделить rate’ы.** Аудио-callback (cpal, ~44.1/48 кГц)只 копирует в lock-free ring buffer; DSP/анализ и control крутить на фиксированных **60 Гц** (как `rate=60` в дампе), а не на аудио-rate. Триггеры/огибающие обновляются в control-тике.
13. **FFT переиспользовать план** (`realfft` planner создать один раз), окно Ханна, hop под 60 Гц. Не пересоздавать буферы каждый кадр.
14. **Биквады вместо TD-фильтров.** LP150/BP800/HP3500 — прямые `biquad`-секции (число секций ≈ `rolloff/6`: 20→~3, 15→~2). Считать по control-кадрам на децимированном сигнале, где допустимо.
15. **OSC одним бандлом.** Вместо ~20 отдельных сообщений в кадр — один OSC-bundle (или пакет) на 60 Гц: меньше syscalls. Поведенчески идентично `format=sample`.
16. **Без аллокаций в горячем пути.** Все буферы (спектр 440, полосы, лаги) — преаллоцировать; `triple_buffer`/`ringbuf` для audio↔worker↔gui/osc.

## D. Удобство и файнтюн
17. **Пресеты под трек** (serde + ron/json): все пороги/гейны/сглаживания/коэффициенты мапперов/сигмоиды. Быстрое переключение.
18. **Калибровочные диапазоны спектра** (`centroid 18..32`, `fms 0..1000`, `sms 100..1800`) — в конфиг: они явно подобраны под конкретный вход.
19. **Метры и превью** в GUI: уровни полос, спектр 440 бинов, кривые сигмоид, индикаторы kick/snare/rythm, монитор OSC.
20. **Профили входа**: device (cpal) / файл, стерео→моно (avg), опц. listen-выход (как `audiodevout`, `Listenvolume`).

## Предлагаемая раскладка Rust-крейта
```
src/
  audio/      # cpal in/out, ring buffer, mono, (опц.) compressor
  dsp/        # biquad-полосы, RMS, FFT-спектр, centroid/fms/sms
  detect/     # kick/snare/rythm (порог→гейт→trigger), beat counters 4/8/16
  control/    # RMS→lag→мапперы→сигмоиды (адаптив, 60 Гц)
  generators/ # (опц.) Low_Base/Mid_Base/High_Mid/Jumper/Zig_Zagger
  osc/        # rosc sender :7700, набор каналов
  gui/        # egui: метры, спектр, сигмоид-редактор, пресеты, OSC-монитор
  config/     # serde-структуры, пресеты (ron), дефолты из 07
```

## Приоритеты (MVP → полный)
> Главная стезя (`10.R0`): **конфигурируемость важнее точного 1:1**. Каждая ступень — с тумблером/крутилками (кроме гейнов и lag).
- **MVP:** вход = **устройство** (+ monitor-источники, без файлового декодера, `10.R6`) → опц. компрессор → моно → 3 полосы → RMS/уровни → kick/snare/rythm → доли 4/8/16 → OSC :7700. Плюс базовый GUI с тумблерами ступеней и крутилками гейнов (`10.R2–R5`).
- **v2:** адаптив (dual-gain, lag stateful, сигмоиды с тумблером `10.R4`) + полный GUI-файнтюн + пресеты (ron).
- **v3:** спектр (centroid/fms/sms) + визуализация.
- **v4 (опц.):** генераторы (Low_Base/…/Zig_Zagger), файловый вход (feature `file-input`), VST3-хостинг (Neutone).
