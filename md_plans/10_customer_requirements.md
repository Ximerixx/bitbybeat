# 10 — Правки заказчика: конфигурируемость (приоритетный слой)

> Эти требования — **над** эталоном `.toe.dir`. Дамп остаётся истиной по значениям/топологии, но главная цель порта — **не просто повторить проект, а сделать его максимально конфигурируемым** через GUI. Где правка конфликтует с «оптимизацией» из `09` (напр. «удалить мёртвую ноду») — **приоритет у правки заказчика** (ноду не удаляем, делаем переключаемой).

## R0. Главная стезя
Максимальная конфигурируемость всего тракта из GUI: любую ступень можно включить/выключить и покрутить, поведение проекта должно быть настраиваемым «на лету», а не захардкоженным.

## R1. Мёртвые ноды — не удалять, а сделать переключаемыми
Заказчик иногда включает их «по ситуации». Поэтому вместо удаления — **bypass-тумблер** (по умолчанию как в дампе: выкл./проходная), но с возможностью включить:
- верхнеуровневый `audiodyna1` (компрессор `−20.6 / 0.638 / +6.9 dB`) — опциональный пре-компрессор;
- `highControlGain` (gain 0.77, postoff +0.3) — альтернативный маппер high (переключатель «использовать `highControlGain` вместо `highControlGain1`»);
- прочие несоединённые ноды — оставить доступными как опции.

➡️ Отменяет пункты `09.A2` (в части «убрать»), `09.A3` («не портировать»), `09.A5` («убрать merge2») — **всё портируем как опциональное**.

## R2. RMS-power во входную DSP-ветвь (переключаемо)
В ветвь сигнала, уходящую в DSP (`InMerge → math1(gain 2.28) → …анализ`), добавить **опциональный узел RMS-power** (аналог `analyze rmspower`), включаемый тумблером. Т.е. на DSP можно подавать либо «сырой» усиленный сигнал, либо его RMS-power-огибающую — по выбору.

## R3. Тумблеры на пред-контрольные ноды (кроме гейнов и lag)
Ноды, стоящие **перед адаптивным контролем**, должны индивидуально включаться/выключаться, **КРОМЕ**:
- **math-множителей (гейнов)** — они всегда в тракте, но с крутилками (см. R5);
- **`lagClearRythmIn_` (lag)** — **всегда включён и сохраняет состояние**: нода помнит последние значения (сглаживание/инерция), это критично. Bypass lag запрещён; при смене параметров состояние (буфер сглаживания) **не сбрасывать**.

Тумблеры нужны как минимум на: `rms` (control-ветвь), пре-компрессор (R1), опциональный RMS-power (R2), и любые вставные ступени. Гейны и lag — без bypass.

## R4. Сигмоида в порогах — переключаемо
Для порогов, идущих на настройки DSP (`Kickthresh`, `Snarethresh`, и при желании `Rythmthresh`), сделать **тумблер «обрабатывать сигмоидой»**:
- **ON**: `thresh = sigmoid(mapper_out)` — как в дампе (`kick 0.7/(1+e^-5.4(x-0.3))`, `snare 0.9/(1+e^-2.1(x-0.5))`);
- **OFF**: `thresh = mapper_out` напрямую (линейный выход аффинного маппера, без сигмоиды).

## R5. Удобные крутилки в GUI
- **Сигмоиды**: редактируемые `ceil` (потолок), `k` (крутизна), `center` (центр) для kick/snare (и rythm, если включим сигмоиду) + живое превью кривой.
- **Все math-множители (гейны)**: крутилки на каждый `gain` (и связанные `preoff/postoff/torange`), а именно:
  - control-ветвь: `math2` (0.64), `lowControlGain` (4.57), `midControlGain` (4.05), `highControlGain1` (1.93) / `highControlGain` (0.77), `kickControlThreshold_math` (3.92), `snareControlThreshold_math` (6.78), `rythmControlThreshold` (4.76);
  - DSP-ветвь: `math1` (2.28), пред-гейны полос `math12` (mid ×2), `math16` (high ×4);
  - пороги/добавки полос: `Lowgain/Midgain/Highgain`, `*thresh`, `*add`, `*smooth`.
- Каждая крутилка — с числовым вводом и диапазоном (дефолты из `07_params_defaults.md`).

## R6. Выбор источника: устройство приоритетно, файл — опционально
- **Абсолютный приоритет — аудиоустройства** (вход через `cpal`).
- Чтобы **не писать лишний код декодирования файлов** (тяжёлые либы вроде `symphonia`): для «проигрывания трека» использовать **loopback/monitor самого устройства** — то есть в списке входных устройств показывать и **monitor выходного устройства** (в PulseAudio/PipeWire это источники вида `*.monitor`; на Windows — WASAPI loopback). Пользователь запускает трек любым плеером, а тулза слушает системный выход.
- **Файловый вход — низкий приоритет / опционально** (за feature-флагом `file-input`), можно вообще не включать в MVP.
- GUI: выпадающий список устройств (вход + monitor-источники), радиокнопка «Device / File(опц.)», индикатор уровня.

Технически на Linux monitor-источники видны как обычные input-devices в `cpal` (backend ALSA/Pulse/PipeWire) → отдельный код не нужен, только фильтр/подпись в списке. На Windows — включить loopback-capture выходного устройства (WASAPI).

> ✅ **Реализовано (см. `11_implementation_notes.md`).** На системе пользователя — PulseAudio; `cpal`/ALSA мониторы не отдаёт. Решение без новых зависимостей: список источников из `pactl list short sources`, захват монитора через ALSA-устройство `pulse` + env `PULSE_SOURCE=<имя>`. В GUI — отдельный комбобокс «pulse source (monitor)».

## Влияние на модель конфигурации (`config/`)
Каждая ступень тракта = `Stage { enabled: bool, params: … }`, кроме гейнов (`enabled` подразумевается true, есть только `params`) и lag (без `enabled`, состояние живёт между кадрами). Пример:
```rust
struct InputCfg { source: Source, device: Option<String>, use_monitor: bool }
enum Source { Device, File /* feature=file-input */ }

struct PreProcCfg {
    compressor: Toggle<CompressorCfg>,   // R1: дефолт bypass
    dsp_rmspower: bool,                  // R2
    control_rms: bool,                   // R3 (rms в control-ветви)
}
struct GainCfg { gain: f32, preoff: f32, postoff: f32, torange: Option<(f32,f32)> } // R5, всегда активен
struct SigmoidCfg { enabled: bool, ceil: f32, k: f32, center: f32 }                // R4/R5
struct LagCfg { lag_up: f32, lag_dn: f32, accel_up: f32, accel_dn: f32 }            // без bypass, stateful

struct Toggle<T> { enabled: bool, cfg: T }
```
Все дефолты — из `07`. Пресеты (serde/ron) сохраняют весь этот граф.

## Приоритеты (обновлённые для MVP)
1. Вход = устройство (+ monitor-источники), без файлового декодера.
2. Тракт со **всеми тумблерами и крутилками** (R1–R5) — это и есть «главная стезя», важнее точного 1:1 повторения.
3. lag — hardwired и stateful.
4. GUI на egui, где всё вышеперечисленное настраивается вживую.
